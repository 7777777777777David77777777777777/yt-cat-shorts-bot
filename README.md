# 時尚寫真：develop 測試指南

這個分支讀取你手寫的 Markdown，生成四張照片，再合成 **無配音、無字幕、有 BGM** 的直式寫真 MP4。
目前 EP01 是「辦公秘書寫真｜黑絲襪與高跟鞋」，主角是虛構的 28 歲成年女性 Ava，預設使用真實風格。

**修改劇本請編輯 [stories/EP01.md](stories/EP01.md)。README 是操作說明，程式不會把它當劇本讀取。**

## 目前四幕內容

| 幕次 | 展示內容 |
| --- | --- |
| 第 1 幕 | 辦公室窗邊全身站姿，建立人物、穿搭與光線參考 |
| 第 2 幕 | 腰部以上人像，轉肩回望鏡頭、輕觸頭髮 |
| 第 3 幕 | 桌旁自然坐姿，與第一幕站姿區隔 |
| 第 4 幕 | 從第一幕直接取景，展示前景一側腳上的完整鞋襪，保留鞋尖與鞋跟 |

四幕維持同一位成年模特兒、同一套象牙白緞面襯衫、深灰窄裙、黑色 20 丹絲襪與七公分黑色高跟鞋。
以妝髮、合身剪裁、自信表情和姿勢呈現寫真感。標題可用中文，不會疊加在照片上。

固定角色資料位於 [Ava 角色檔](assets/characters/ava/profile.md)，集中保存身分、外觀、身形與具名參考圖片。
本集服裝只在 EP01 的 `## 服裝` 寫一次，各幕共用；場景、動作、表情與鏡頭分開設定。
第 1 幕附上這兩張主角圖建立當集全身穿搭，第 2～3 幕附上**同一組主角圖＋當集第 1 幕圖片**。
本範例第 4 幕直接使用第一幕圖片指定區域，不再呼叫產圖 API，也不重畫腳部或鞋襪。
主角圖固定五官、髮型與身形，第一幕固定當集衣服與鞋襪；場景、姿勢及表情依各幕描述變化。
肖像圖優先定義五官，全身定妝照定義自然比例；參考照片的站姿及全身構圖不會作為各幕構圖要求。
當幕的畫面要求會放在實際提示詞末段，細節鏡頭明確排除頭部與全身構圖。這些是提示詞約束，生成後仍需人工確認。
主角圖中的灰色緊身衣與白襪不會覆蓋劇本穿搭。參考不會逐幕接續，以免偏差累積。
提示詞會要求保留臉部、髮型、衣料、釦子、腰頭、裙長、絲襪透明度、鞋型與跟高；這能改善一致性，仍不能保證細節完全不變。
目前不會自動判定第 1 幕服裝是否正確；人工檢查時若發現參考圖已經偏離設定，應先修改該幕再重新測試。

## 1. 修改劇本

1. 開啟 [stories/EP01.md](stories/EP01.md)，確認 GitHub 分支是 **develop**。
2. 修改本集的服裝、共同場景，以及各幕動作、表情與鏡頭；長相與身形統一修改 Ava 角色檔。
3. 保留檔案的標題結構，修改完提交到 **develop**。

| Markdown 區段 | 填寫內容 |
| --- | --- |
| `# EP01` | 集數 ID，使用 EP 加數字 |
| `## 標題` | 影片標題，保留你寫的文字 |
| `## 氛圍` | 展示風格或氛圍，會加入產圖提示詞 |
| `## 標籤` | 半形逗號分隔，可留空 |
| `## 角色檔` | 指向 `assets/characters/` 內的 `.md` 角色檔；本例為 `assets/characters/ava/profile.md` |
| `## 服裝` | `- 上衣：…`、`- 下身：…`，或改用 `- 連身衣：…`；另填襪類、鞋款及可選的配件 |
| `## 共同場景` | `- 地點：…`、可選的 `- 光線：…`，各幕沿用 |
| `## 第1幕` 至 `## 第4幕` | 固定四張照片 |
| `### 動作` | 必填，寫當幕姿勢及行動，衣服細節沿用本集服裝 |
| `### 地點` | 選填，該幕另換場景；未填就沿用共同場景 |
| `### 表情` | 選填，描述情緒、目光與眉眼；臉不入鏡時省略 |
| `### 鏡頭` | 景別、角度、主體、入鏡範圍、排除、臉部入鏡，以及可選的裁切範圍／取景來源 |

服裝每項用一行 `- 欄位：內容`，顏色、材質、版型及長度寫在該項內容裡。四幕不另外指定服裝；新一集只需更換這份設定。
上衣＋下身與連身衣擇一，襪類及鞋款必填；沒有時明確寫「無」。例如洋裝用連身衣，搭配襪類與鞋款即可。

鏡頭景別接受「全身、半身、肖像、服飾細節」。第一幕使用全身，建立當集完整穿搭。
角度預設平視，全身／半身／肖像有預設入鏡範圍；服飾細節需明確寫主體與入鏡範圍。
構圖文字仍可能被產圖模型忽略；`裁切範圍` 則由程式在合成前實際套用。
四個數值分別為左、上、右、下，使用圖片尺寸的 0～1 比例。區域若不是 9:16，會擴大至相同比例並保留原指定區域，填滿畫面而不拉伸。
只有裁切範圍時，先生成該幕，再裁切並保留未裁切版本；第二幕使用這個方式。
指定取景來源時，直接裁切前面已完成的幕，不送產圖請求；例如第四幕：

```markdown
### 鏡頭
- 景別：服飾細節
- 主體：前景一側腳上的鞋襪搭配
- 入鏡範圍：小腿至前景完整鞋襪，保留鞋尖與鞋跟
- 臉部入鏡：否
- 取景來源：第1幕
- 裁切範圍：0.33, 0.69, 0.64, 1.00
```

裁切不會新增細節或變換姿勢，放大後的畫質受原圖限制。本範例座標適用於居中全身站姿，若新一集腳部位置不同，需調整座標。
細節幕及裁切幕不額外推拉，避免鞋尖或鞋跟再被切掉。首圖本身若缺少鞋尖或鞋跟，裁切也無法補回。
欄位／像素測試不能保證生成的人體正確；多手等產圖錯誤仍需檢視原圖。

秒數、BGM、畫風及輸出格式由 workflow／程式預設值管理，不必在各幕重複填寫。

不需要填旁白；舊 Markdown 即使保留 `### 旁白`，寫真模式也不會朗讀或製成字幕。
表情描述會直接加入該幕產圖提示詞，定妝照不會鎖死表情。
程式會在產圖前檢查欄位錯字、重複、缺少服裝項目、景別與臉部入鏡設定矛盾、臉不入鏡卻填表情等可判定衝突。
這些檢查不會判斷自然語言描述中的所有矛盾，也不能代替生成後的畫面檢查。

舊式 Markdown 的 `## 角色`、`## 主角參考`、`### 畫面` 仍可讀取。使用新角色檔時請移除集內的角色與參考圖副本，避免兩份設定衝突。
沒有指定角色檔或主角參考的其他劇本不會自動套用 Ava。角色檔不接受服裝或表情欄位，這些由集內設定負責。
程式直接讀取你的內容，不呼叫 AI 改寫劇本或添加標題尾綴。
你也可以新增 `stories/EP02.md` 等檔案；目前只接受 `stories/` 內的 **Markdown（.md）劇本**。

## 2. 手動執行測試

1. 前往 [GitHub Actions](https://github.com/7777777777777David77777777777777/yt-cat-shorts-bot/actions)。
2. 點原有的 **Hourly 6x Cute Cat YouTube Shorts Factory** → **Run workflow**。
3. **Branch 務必選 develop**；`main` 是正式發布流程。
4. `script_path` 填 `stories/EP01.md`，`visual_style` 選 `photorealistic`（真實風格）。
5. `scene_seconds` 預設每張 5 秒，四張共 20 秒；亦可選 4 或 6 秒。
6. `bgm_path` 留空使用程式合成的簡單 96 BPM 無人聲配樂，再執行。

如果表單沒有顯示上述欄位，develop 程式也會使用這些預設值。
其他可選畫風：`cinematic_3d`、`cel_anime`、`watercolor`、`clay_stop_motion`、`paper_diorama`。

develop 的 workflow 名稱是 **Handwritten Script Preview (develop only)**；左側顯示名稱可能仍取自 main。
執行時先檢查劇本、角色檔、參考圖及自訂 BGM，成功後才產圖；缺檔、壞圖或設定衝突時會先停止。

替換配樂時，將有權使用的 `.wav`、`.mp3` 或 `.m4a` 放進 [assets/bgm/](assets/bgm/README.md)，
提交到 develop，再將 `bgm_path` 填為例如 `assets/bgm/my-track.mp3`。
音樂會循環至片尾，並調整音量及淡入淡出。預設合成伴奏不需要額外音樂 API 或金鑰。

## 3. 下載 MP4

執行完成後，開啟該次紀錄，在 **Artifacts** 下載 `script-preview-…`，解壓縮並播放 **preview.mp4**。

成品為 1080×1920 直式 MP4，照片有輕微推拉與柔和轉場，音軌只有 BGM；沒有配音、字幕、進度條或飄浮粒子。
下載檔也包含每幕圖片、實際使用的主角圖副本、BGM、產圖提示詞，以及自動產生的 `metadata.json` 執行紀錄。
紀錄內包含產線版本、執行 commit、角色檔雜湊、本集服裝、場景、鏡頭、秒數與用量。
`scene_outputs` 區分生成與裁切，保存來源幕、來源圖雜湊、要求及實際裁切座標、放大倍率；裁切幕的 `.plan.txt` 是取景紀錄，並非 API 請求。
不需要你編輯 JSON。
失敗時仍會備份已取得的素材與錯誤資訊。

目前是靜態分鏡合成預覽；真正的角色肢體動畫仍在暫緩計畫中。

## 設定與費用

使用既有 repository Actions secret **GEMINI_API_KEY** 生成四張圖片。
預設模型是 `gemini-2.5-flash-image`；如需其他相容圖像模型，可設定 Actions variable `GEMINI_IMAGE_MODEL`。
每個生成幕最多一次產圖請求，失敗就停止，不產生純色備援圖；產圖依 Google 專案計費。
本範例共三次產圖請求，第四幕裁切不呼叫 API，仍輸出四幕。
生成幕包含主角圖片輸入，第二及第三幕另加第一幕圖片；實際 token 以 API 回報為準，不估算或保證價格。

測試新版請用 **Run workflow → develop** 建立新執行；舊紀錄的 **Re-run jobs** 會沿用當次 commit，不會取得最新修正。
可在日誌的「產線版本／commit」及 `metadata.json` 核對實際版本。

推送劇本不會自動產圖，只有手動執行才會呼叫產圖 API。本測試不讀寫 Sheet、不上傳 YouTube，也不帶入其 credentials。
公開儲存庫內的劇本、日誌與下載產物可被其他人看到；develop 分支不是私密空間。

只檢查格式、不呼叫 API，可在安裝專案依賴後執行：

```bash
python script_preview.py --script stories/EP01.md --validate-only
```
